## What landed

1. **Per-fact validator.** `duplicate_fact`, `evidence_span_mismatch`, `evidence_outside_input`, `credential_in_fact`, and `target_outside_context` drop that fact. Fence, schema, injection, and entity-guard failures still reject the attempt. An invented reason span is cleared; a span that matches the cited record is kept.
2. **Stated flag.** `OutFact.stated`. `provenance_for_statement` returns `user_supplied` only when the record is owner-authored **and** the fact is stated. Same-message test: "ugh work again" → stated fact `user_supplied`, interpretation `inferred`.
3. **Active facts in the prompt.** `PostgresJobs._active_facts_for_prompt` lists every active visible fact, with no 50/80 cap.
4. **Topic aliases.** Migration `0004_subject_aliases.sql`. The backfill writes EN / AR / Arabizi aliases (phone = mobile = iphone = samsung = موبايل = تليفون, plus a short Dubai-life seed from `docs/references/residence-ontology-tree.md`). `search_candidates` subject channel matches query tokens to labels, path segments, and those aliases. Test: "phone" and "mobile" retrieve "Karim bought an iPhone 13 Pro Max" on channel `subject`.
5. **Places.** Prompt asks for places visited, likes, dislikes, preferences, `place_type`, and food/outings under `events`. Applier stores `place_type` and `reason_*`.
6. **One taxonomy.** Prompt roots are `CLUSTERS` + `HELD_BACK_ROOTS`. Proposal only: `db/proposals/cluster_roots.sql` (not under `migrations/`, not executed).
7. **Days and chunks.** `daytime.local_day` is used by triage, `split_import`, and both bridge enqueue paths. `20:30Z` in `Asia/Dubai` is the next local day. `TM_PACKET_TOKEN_BUDGET` defaults to 4000. Chunk jobs have chunk-aware idempotency keys. A later chunk's prompt includes facts applied by the earlier chunk. `split_import` uses the same owner-device / internal pool rule as ingest.
8. **`PROMPT_VERSION = extract@4`.** Re-runs drop duplicate facts instead of rejecting the day, so existing intervals stay.
