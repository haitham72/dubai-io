## Item 0 · Topic Forget

Source Forget now uses the same owner advisory lock as live ingest. The transaction finds affected topic sessions, deletes each association that has lost its last supporting record, and revalidates each affected inferred hypothesis. Fewer than two surviving sessions erase the fact and its embedding. When valid replacement evidence exists, the fact cites two surviving sessions. The same transaction increments `privacy_revision` and `facts_version`.

Postgres regressions exercise the authenticated `/hypotheses`, `/vault/graph` and `/context` paths. Unrelated Forget preserves the hypothesis. Losing a qualifying visit retracts it. Another matching record from that visit keeps the hypothesis qualified and replaces its citation. The full memory run was **407 passed, 8 skipped**.

## Ingest

`apps/api/app/ingest_routes.py` mounts the Quest-authenticated `/api/ingest` endpoints. Provider fetching, incremental OAuth and storage live in `app/connectors/e3_*.py`. Consent defaults off and is isolated by owner and source. Each source gets its own encrypted grant and consent revision. Source-off discards its local grant and prevents later pulls. An in-flight pull rechecks consent before writing. Provider/account state and source receipts are in the local temporal-memory Postgres database. OAuth callback authorization codes are removed from Uvicorn access logs.

The Google paths cover Gmail primary mail over the last 90 days with a conservative 50,000-byte ingestion budget, Calendar primary events in the previous and next 90 days, and YouTube likes, subscriptions, playlists and uploads. YouTube likes carry the observation time. Calendar private and cancelled entries are excluded. Held-back sensitive data is screened before queuing. The upload endpoints reuse the engine's Takeout and WhatsApp parsers. The API uses owner-local day buckets and bounded batches, then calls the owner-scoped memory bridge. Stable IDs and the bridge fingerprint prevent duplicate imports. Repeat pulls recover a raw record if its first call stored it before enqueue failed.

Every endpoint requires the verified Quest session. Use the cookie or `X-App-Session`. Owners come from that session.

## Google console and run sheet

Set `GOOGLE_INGEST_REDIRECT_URI` if it differs from the existing API origin. Credentials and the connector encryption key stay on the server. The redirect must return to the Quest session that started it. Google account subjects are verified by Google and bound to one Quest owner on first connection. 1. Start E1 with the real memory HTTP bridge and its local Postgres. Set the server-side `TM_BASE_URL` and the matching `TM_DATABASE_URL`. Device-token provisioning uses E2's memory-token service or the configured server-only `TM_ADMIN_TOKEN`.
2. Sign in on PC with E2. Enable Gmail, call `/google/gmail/connect`, and finish Google consent in that PC session. The callback acknowledges the grant without returning credentials.

5. Exercise source Forget only on a source you intend to erase. Its own status and memory evidence should disappear.

## Integration dependencies and open verification

- `apps/desktop/electron/main/index.ts:77` returns only `sync.runSyncNow().status`. `continuousSync.ts:71` collects local candidates and marks them seen without any owner binding or HTTP handoff. E2 needs to parse and redact candidates through the existing local importers, read server source consent before scanning, obtain the current Quest owner's `/api/identity/memory-device-token`, submit via the desktop DTO above, and mark the hash seen after the bridge receipt. It should keep the token in the Electron main process. The two-token owner and consent gates were verified on Postgres.
- E3 day packets use the existing `extract.day` bridge contract. E1 must configure the day worker with `TM_WORKER_RUNNER=claude-cli` and its configured Haiku model for subscription runs, or `TM_WORKER_RUNNER=lmstudio` and the configured Qwen model for local runs. Automatic Qwen selection for internal day packets is a worker/start-stack integration item. The current bridge supplies neither a day pool selector nor a per-job runner override. E3 does not initiate model calls directly.
- Connect UI, real Google consent, and desktop posting remain E1/E2 manual integration checks. No real exports were committed.
