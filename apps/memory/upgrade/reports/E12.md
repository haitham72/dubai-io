## Endpoints wired (before → after)

| Surface | Before | After |
|---|---|---|
| Feed (`/`) | `lib/feedFixture.ts` fixtures only | `GET /api/community/feed` via `getFeed()`; sort pills (new/top/hot) and lane tabs (For you / Following / Communities) filter real posts; a new post appears at the top straight away (For-you lane = discovery picks first, then the rest of the feed, deduped) |
| Post actions | none | like toggle `POST …/reactions`, bookmark `POST/DELETE …/bookmarks`, threaded replies `GET/POST …/comments` (`parent_id`), edit `PUT …/posts/{id}`, delete `DELETE …/posts/{id}` (own posts only, two-tap confirm). All counts come from the API; optimistic UI reverts + shows the API error on failure |
| People | `seedProfile` fallback | follow/unfollow `POST/DELETE /api/community/follows/{handle}` from post cards and `/u/[handle]`; create/edit profile form (`PUT /api/community/profiles/me`) with handle, display name, bio, area, interests, age band, privacy. API's 18+ refusal (403/422) is shown verbatim. Signed-in users never see `seedProfile` — API failure shows an honest error, no fixture |
| Groups | list-only fixtures | `GET/POST /api/community/groups`, join/leave, group detail + group feed + group composer (`…/groups/{id}/posts`). Private groups show the API's fencing (404/hidden); non-member UI shows "not visible" |
| Search | none (icon was dead) | `/search?q=` over `GET /api/community/search` — groups, people, posts sections |
| For you | hard-coded "why" strings | `GET /api/community/discovery`; "Why this?" chip renders `why_this`/`why_chip` from the API response only. Hard-coded `why` text deleted from `lib/seed.ts`. Cold-start public-group fallback labelled by the API (`origin`/`demo_data`) |
| Inbox | seeds always | real-first `GET /api/community/inbox`, mark-read `POST …/notifications/{id}/read` + `…/read-all`; `seedNotifications` only when signed out or API unreachable, with `Demo data` pill |
| Create | posted but feed never showed it | posts via `POST /api/community/posts`, redirects to `/` where the post is at the top |
| Memory panel | already real | unchanged (consent toggles + Forget via `/api/community/memory/*`) |

Honest-state rules kept: fixtures render only when signed out or the API is
unreachable, always with the `Demo data` pill; no fake counts; no fake "Posted".

B likes and replies → A gets the reply notification and sees the like count —
plus failure paths: private-group post invisible to non-member (API 403/404 +

reply to a deleted post → API error surfaced (unit-tested in the card).

## Founder checklist (real check — needs real Gmail, run on the PC)

With `scripts/dev/start-all.ps1` up (community API :8060, website :3060, api :8000):

1. Founder signs in with Google on the PC website (`/signin`), QR-pairs the iPhone if needed; both show the founder's name — no demo user.
2. Founder creates a community profile at `/profile` (handle, interests); under-18 band must be refused by the server.
3. Founder posts from `/create`; the post is at the top of the feed immediately.
4. Tester Gmail signs in on a second browser/device, follows the founder from the post card or `/u/<handle>`, sees the post in the **Following** lane, likes it and replies.
5. Founder sees the like count and the reply in `/inbox`; tester sees the founder's reply likewise. Data stays isolated between the two accounts.
6. Tester creates/joins a public community and posts in its group feed; a private community the tester isn't in must not show its posts anywhere (feed, search, group page).

## Known limits / notes for the integrator

- Group "Request invite" for private groups calls join and shows whatever the
  API returns (pending/approval states surface as API errors, not fake success).
- Discovery "For you" merges API discovery picks with the rest of the feed so a
  new post is always visible on the default lane; ordering inside is
  discovery-first then feed order.
- `apps/community/AGENTS.md` was auto-generated by `next dev` (Next 16 agent
  rules block); committed to keep the tree clean per its own note.
- The two-user e2e needs `playwright` in the api venv; it skips (not fails)
  everywhere else.
