# E13a · Memory lowering, explicit recall, and account deletion

Branch `e13a/lower-and-delete` includes the D19 snapshot at `b0785c3` and reconciles `origin/main` through `4c946dc` (including `b3f9e76`). PR #9's ID-scoped lazy embedding backfill and facts-version checks coexist with E13a's owner embedding cache invalidation.

## D19 and D19b

- Passive context, search, Today, and recommendation paths retain the 0.10 cutoff. Vault can display lowered items and their evidence. Lower and Restore preserve the underlying facts and records.
- Explicit owner-device search, ID recall, and Vault fact opens bypass the weight cutoff. Messenger reads candidates first and boosts only returned facts whose evidence sources pass consent. Admin, worker, and passive reads do not trigger boosts.
- A recalled fact receives `min(1.0, max(0.35, effective_weight + 0.25))`. Recall clears its item lowering, resets the age clock, and lets that fact override earlier source, subject, or record lowering. The override applies to that fact alone, and a later Lower can suppress it again. Recall preserves `valid_from`, status, provenance, and Rule 9 visit counts.
- Both `public.schema_migrations` and `tm_dbg_routes.schema_migrations` on Postgres `:5442` had no version 8 row before the edit. The recall columns and view changes therefore live in unmerged `0008_memory_controls.sql`.

## Deletion and Google Limited Use

- Deletion requires Redis. Temporal memory purges before changing database state and again after the deletion fence commits. The API clears owner keys from configured Redis endpoints, removes the Community context key and interest projection cache, clears the in-process Today cache, and revokes app sessions and memory tokens. The optional Community purge hook is wired for when E14 supplies it.
- The database fences the owner and leased work, increments the generation and facts version, and revokes memory device tokens. Sibling worker processes rely on the shared `owner_deleted` database check in retrieval. Context cache lookups also compare the owner version, so another process cannot serve a pre-deletion context pack.
- The backup stores a random surrogate UUID plus aggregate counts for an allowlist of coarse topic clusters. It contains no owner ID, raw text, names, email addresses, phone numbers, tokens, or credentials. Gmail, Calendar, YouTube, and YouTube Takeout evidence are excluded, including mixed-provenance rows. The route and tool isolation test verifies that the only application reference to the backup table is the deletion-time INSERT.
